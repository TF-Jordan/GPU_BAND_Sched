\chapter*{Résumé}
\addcontentsline{toc}{chapter}{Résumé}

Dans un cluster Proxmox configuré de manière classique, les ressources matérielles restent principalement gérées au niveau de chaque nœud. Ainsi, une machine virtuelle peut être refusée sur un nœud saturé alors que d'autres nœuds du cluster disposent encore de ressources suffisantes. Cette situation limite l'exploitation globale du cluster et entraîne un gaspillage des capacités disponibles en mémoire vive, en processeurs, en accélérateurs graphiques et en entrées-sorties de stockage.

\emph{FusionCore} est un système de mutualisation des ressources conçu pour améliorer l'utilisation d'un cluster Proxmox composé de trois nœuds ou plus, sans modification du code source du noyau Linux, de QEMU ni de Proxmox. Le système s'appuie sur un mécanisme de déplacement distant des pages mémoire peu utilisées, un ajustement dynamique des processeurs virtuels, une organisation contrôlée de l'accès aux accélérateurs graphiques et une politique de migration automatique. Pour la migration, les agents chargés de la mémoire, du processeur et de l'accélération graphique émettent des signaux selon leurs propres critères. L'agent de migration analyse ces signaux en tenant compte de l'état global du cluster afin de décider, lorsque cela est pertinent, d'une migration à chaud ou à froid.

L'implémentation repose sur un démon écrit en Rust, déployé sur chaque nœud, et sur un contrôleur écrit en Python chargé de construire une vue globale du cluster. Les échanges entre nœuds utilisent un protocole dédié et sécurisé, tandis que l'intégration avec les machines virtuelles reste transparente pour l'utilisateur. Cette architecture permet de préserver la compatibilité avec les installations Proxmox existantes tout en améliorant l'exploitation collective des ressources disponibles.

La validation du système s'appuie sur des tests automatisés, des scénarios de charge et des tableaux de bord de supervision. Les résultats présentés permettent d'évaluer le comportement de \emph{FusionCore} sous pression mémoire, lors de l'ajustement des ressources et pendant les opérations de migration. Ils montrent que l'approche proposée est pertinente pour un environnement académique cherchant à valoriser un ensemble de machines existantes au sein d'un cluster commun.

\textbf{Mots-clés.} Virtualisation, cluster Proxmox, mutualisation des ressources, mémoire distante, ordonnancement dynamique, partage d'accélérateurs graphiques, migration automatique, supervision.

\chapter*{Abstract}
\addcontentsline{toc}{chapter}{Abstract}

In a conventional Proxmox cluster, hardware resources are mainly managed at the level of each individual node. As a result, a virtual machine may be rejected on a saturated node even though other nodes in the cluster still have available capacity. This situation limits the overall use of the cluster and leads to wasted memory, processing power, graphics acceleration capacity and storage input--output resources.

\emph{FusionCore} is a resource-pooling system designed to improve the use of a Proxmox cluster composed of three or more nodes, without modifying the source code of the Linux kernel, QEMU or Proxmox. The system relies on remote movement of rarely used memory pages, dynamic adjustment of virtual processors, controlled access to graphics accelerators and an automatic migration policy. For migration, the memory, processor and graphics acceleration agents send signals based on their own criteria. The migration agent then analyses these signals together with the global state of the cluster in order to decide, when relevant, whether a live or cold migration should be performed.

The implementation is based on a Rust daemon deployed on each node and a Python controller responsible for building a global view of the cluster. Inter-node exchanges use a dedicated and secured protocol, while the integration with virtual machines remains transparent for the user. This architecture preserves compatibility with existing Proxmox installations while improving the collective use of available resources.

The validation relies on automated tests, load scenarios and monitoring dashboards. The presented results make it possible to assess the behaviour of \emph{FusionCore} under memory pressure, during resource adjustment and during migration operations. They show that the proposed approach is relevant for an academic environment seeking to make better use of existing machines within a shared cluster.

\textbf{Keywords.} Virtualization, Proxmox cluster, resource pooling, remote memory, dynamic scheduling, graphics accelerator sharing, automatic migration, monitoring.
